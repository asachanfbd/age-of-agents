Gated Feature Pipeline — Gate review

One stepper, one panel. Only stages where a human actually decides something get a slot — everything the pipeline does autonomously is bundled behind a single review.

What changed from the last pass
  • Implement, Test and Code review are folded into one Dev stage — autonomous end to end, one gate when it's done.
  • Retro is the pipeline's last stage in this same stepper, not a separate tab — it starts automatically the moment Dev above is approved, runs asynchronously (never blocks what Dev already shipped), and its proposal is split into two independently-approvable sections: project-level and global (catalog/).
  • The old "Revision ripple" and "Backend model" tabs are gone — they were explaining mechanics, not showing UI. That reasoning now lives in chat, not this doc.
  • Every stage can carry pre-stage questions (asked before the agent drafts anything) and, separately, open questions left inside a review — try Architecture below.
